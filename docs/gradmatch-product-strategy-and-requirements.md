## 1. 一句话定位

GradMatch 是一个**证据驱动的研究生选择工作台**：把分散、易变的官方招生信息，转化为用户能核验、能比较、能执行的候选项目清单和下一步行动方案。

它不是院校排行榜、导师口碑站、保录取服务，也不承诺录取概率。LLM 的角色是理解用户表达、追问缺失条件和解释方案；招生事实、资格条件和排序必须来自可追溯的数据与规则。

产品与团队的核心经营目标是形成可持续利润，但盈利必须建立在可验证的用户决策价值上。公开信息聚合不是护城河；可收费能力来自年度化证据、资格与范围校验、学硕/专硕和成本/职业路径比较、变更提醒及可执行行动。人工服务、报考季软件权益和后续 B 端产品分别验证、分别核算，任何商业关系不得改变自然结果。

## 2. 为什么值得做

研究生选择不是简单地选“学校”，而是在特定入学年度、特定招生路径下，选择一个具体的培养单位和项目。用户要同时处理报名资格、考试科目、学习方式、学费、校区、招生计划、复试规则、时间节点与个人偏好；这些信息分散在研招网、招生单位和院系页面，且会逐年变化。

教育部 2026 年硕士招生工作管理规定明确了招生单位、学科专业、初试与复试等年度化管理框架；全国 2025 年共招收硕士生 123.68 万人，说明市场规模大，但对单个用户仍是低频、季节性强、可能高影响的决策。招生人数不能推导付费需求或利润。[教育部招生规定](https://www.moe.gov.cn/srcsite/A15/moe_778/s3261/202509/t20250918_1413836.html) [教育事业统计公报](https://www.moe.gov.cn/jyb_sjzl/sjzl_fztjgb/202607/t20260706_1442870.html)

### 要解决的核心问题

1. **信息碎片化**：用户很难在同一标准下比较项目。
2. **信息时效性差**：旧招生简章、论坛经验与当年规定混在一起。
3. **选择缺少依据**：用户得到“冲、稳、保”结论，却不知道条件、证据和不确定性。
4. **行动难落地**：比较后仍不知道该核验什么、准备什么、何时完成。
5. **通用 LLM 的可信度不足**：没有受控证据时，模型可能编造时间、费用、资格或项目事实。
6. **专业层级混乱**：学科门类、一级学科、专业学位类别、六位专业/领域和学校方向被当作同一概念。
7. **学硕/专硕被标签化**：用户得到“含金量”判断，却看不到培养、考试、成本、深造和职业路径差异。
8. **招生分母被混用**：含推免总计划、统考名额、专项计划和实际录取没有分开。
9. **读研成本被低估**：只看每年学费，忽略学制、住宿、奖助、生活和机会成本。
10. **就业数据口径错配**：学校整体就业率、行业平均工资或本科数据被当作具体硕士项目结果。

## 3. 产品原则与非目标

### 3.1 产品原则

- **项目优先，而非学校标签优先**：核心对象是“某入学年度 × 某培养单位 × 某专业项目 × 某招生路径”。
- **事实必须带证据**：每一个时效性字段都显示来源、适用年度、发布日期、核验时间和状态。
- **未知就是未知**：缺失字段只能显示“未公布/待核验”，不能用相近项目、往年或模型猜测补全。
- **用户拥有决定权**：平台展示规则、权重、依据与风险；用户可以调整偏好并查看非个性化结果。
- **最小化收集**：先通过目标、方向、硬约束形成有用结果，首期不要求上传成绩单、身份证件或财务材料。
- **先证明价值，再扩覆盖与流量**：使用真实决策质量、数据正确性和回访来衡量，而不是下载量或注册数。

### 3.2 首期明确不做

- 不给“上岸率”“录取概率”“保录取”或“唯一最适合”结论。
- 不做未经核验的导师好坏评分、匿名口碑排行或“内部消息”。
- 不把院校付费、广告预算、咨询佣金写入自然排序或推荐理由。
- 不在无可靠数据和更新能力时宣称全网覆盖。
- 不收集并转卖用户线索，不将用户对话用于训练模型。

## 4. 首期目标用户与任务

### 4.1 首期用户

首个微人群假设为：准备 2027 年全国统考、把北京和全日制作为硬约束、选择计算机相关方向、已有初步候选但因资格、统考名额、科目迁移或总成本冲突无法收敛的用户。该人群和任务必须用一手访谈与真实任务回放验证；尚不能写成已成立画像。试点必须展示明确包含和排除的地域、学习方式和招生类型，不能把“统考”误解为覆盖所有硕士招生路径。

后续把推免、国内博士、港澳和海外申请作为独立规则包与数据模型建设；不得仅在现有页面加几个筛选项后混合上线。

### 4.2 用户任务

| 用户问题 | GradMatch 应提供的结果 |
| --- | --- |
| 我能报什么？ | 基于已确认硬约束的候选项目，按“符合已知条件、信息不足待确认、不符合已知条件”三态返回，并逐项说明依据。 |
| 这些项目有什么区别？ | 可比较的年度字段、差异高亮和对应官方来源。 |
| 我为什么要保留或排除它？ | 可解释的适配理由、冲突项、信息缺口和风险提示。 |
| 我为什么读研、学硕还是专硕？ | 读研目标卡，以及培养、考试、实践、成本、深造和职业路径的证据化比较。 |
| 真正留给统考的名额是多少？ | 总计划、推免、统考、专项、联合培养和实际录取的分口径展示。 |
| 读完需要付出什么？ | 目标年度学制、学费、住宿、奖助与用户自填生活/机会成本。 |
| 毕业后可能走向哪里？ | 带人群、届次、样本和定义的职业路径及结果证据；没有匹配证据时只显示更宽范围背景。 |
| 下一步应该做什么？ | 带日期、官方链接、材料或核验项的行动清单。 |
| 信息变了怎么办？ | 来源版本、变更记录、订阅提醒和纠错反馈入口。 |

使用者通常是考生；购买者可能是考生或家长；同学、家长、老师可能是影响者；考生本人对个人事实和最终取舍拥有决定权。付款、分享或邀请不授予第三方查看完整偏好、对话或替考生修改方案的权限。

除功能任务外，研究必须记录用户的焦虑、家庭压力、身份期待和决策自主权。产品不利用焦虑制造付费紧迫感；减少错误、确认没有适合项目、等待正式信息或暂缓考研都可以是有效结果。

### 4.3 报考资格三态合同

资格判断只能返回以下三种状态，页面、接口、规则和 AI 解释必须使用相同语义：

| 状态 | 判定条件 | 产品动作 |
| --- | --- | --- |
| `eligible_known` 符合已知条件 | 所有已发布且适用的硬性规则均满足；不存在影响结论的未知项 | 可进入偏好比较，但明确“不代表录取可能性”。 |
| `needs_confirmation` 信息不足待确认 | 官方规则未发布、条款含歧义、来源冲突，或用户缺少必要背景信息 | 不得给出肯定/否定结论；列出缺口、官方来源和向招生单位核验的问题。 |
| `ineligible_known` 不符合已知条件 | 至少一条已发布且适用的硬性规则明确不满足 | 默认排除；展示具体规则、用户事实和证据，允许用户纠正自己的事实。 |

“可能符合”“大概率能报”等模糊状态不得出现。特别处理同等学力、跨专业、工作年限、前置学历/学位、境外学历认证、非全日制定向就业等情形；无法结构化的例外一律进入 `needs_confirmation`。

### 4.4 研究结论与首个试点

两个抽样框、题型和年份不可直接合并的历史调查都出现了专业、学校、城市、导师/培养与报考难度，只能说明这些主题值得进入用户研究。2019 研招网调剂期网络调查的择校题最多选三项，网页百分比为选项构成且逐题分母未披露；麦可思 2022 届“正在读研”子样本量也未公开。两组数据都不得决定默认权重或证明当前全国人群偏好。完整边界与来源见 [`docs/research/china-masters-decision-factors-and-outcomes.md`](research/china-masters-decision-factors-and-outcomes.md)。

首个纵向试点使用 [`pilot-scope-2027-v1`](research/pilot-scope-2027-v1.md) 冻结目标用户、北京地域、全日制统考路径、工程原型 3 个计划项目和邀请制 10 项目分母。学硕候选代码覆盖 0812/0835/0839，专硕候选代码覆盖 085404/085405/085410；清单中的计划身份不等于 2027 已招生。正式目录发布前全部时效字段为 `pending_publication`；若项目停招、改码、拆分或合并，只能关闭计划实体并发布新的 `CoverageManifest` 版本，不能改写 V1。

学硕和专硕在国家层面地位同等、培养定位不同。产品只比较具体项目的研究/实践取向、考试、培养、成本、读博与职业路径，不生成“含金量”或“社会地位”总分。

## 5. 核心体验与功能需求

### 5.1 端到端流程

1. **确认范围与目标**：访客先确认 2027、北京、全日制、统考和计算机相关方向这一冻结范围，只询问会改变候选集的其他硬条件；范围外请求明确标记为当前未覆盖。
2. **形成候选集**：只使用已发布规则和证据返回资格三态；LLM 可选且不阻塞这一流程。
3. **比较关键差异**：对 2–5 个候选展示资格、统考名额、科目迁移、总成本、培养、职业背景和未知项。
4. **形成决策快照**：记录结果枚举、保留/排除/延后项目、用户确认理由、关键未知、下一步、复查日期和证据版本；不显示概率或标量置信度。
5. **再要求账户**：访客先完成一次安全决策闭环；只有保存、跨设备同步、更新提醒、协作或购买时才要求注册。
6. **回源与纠错**：用户可跳转官方页面、提交带官方链接的纠错；审核后发布变更并幂等重算受影响方案。

偏好因素必须由版本化 `PreferenceFactorDefinition` 定义名称、语义、允许证据、适用范围、未知处理和解释模板。“最多三项并分配 100 点”是 P1 实验，不是获得安全结果的前置条件；同时测试排序、成对比较和自然语言取舍。

候选分组规则：

- **优先比较**：资格状态为 `eligible_known`，并且在用户已确认的可权衡偏好中表现较高。
- **备选比较**：资格状态为 `eligible_known`，但偏好适配度较低或存在明确取舍。
- **待核验**：资格状态为 `needs_confirmation`；不能进入肯定式推荐文案。
- **已排除**：资格状态为 `ineligible_known`，或用户主动排除。

偏好排序必须展示参与计算的偏好、权重、缺失值处理和并列规则。相同偏好结果保持真实并列；证据较完整只能影响可信状态，不能让项目显得更适合。渲染可以按项目名称做稳定的非语义顺序。系统不得输出综合“上岸分”“录取分”或把比较优先级描述成“冲、稳、保”。

### 5.2 MVP 页面与验收要求

| 页面 | 必须能力 | 验收条件 |
| --- | --- | --- |
| 目标与专业页 | 读研目标、目录导航、学硕/专硕比较 | 用户能说明目标并理解当前选择的目录层级和学位类型；不得显示含金量总分。 |
| 选择标准页 | 路径、年度、硬约束、偏好和权重 | 用户可跳过非必要问题，并随时修改已确认事实。 |
| 对话访谈页 | 渐进追问、事实卡确认、隐私提示 | 对话不要求证件或完整成绩单；未确认内容不能作为硬筛选依据。 |
| 项目发现页 | 搜索、筛选、数据年份/状态 | 每张卡至少显示适用年度、资料状态与来源入口。 |
| 项目详情页 | 资格、科目、学制、费用、计划、复试等字段 | 每个展示的时效性事实可回到原始链接；无来源字段明确标记。 |
| 对比页 | 差异高亮、缺失值、来源状态 | 用户可在同一表内解释保留/排除原因。 |
| 成本与职业页 | 总成本公式、职业路径、结果范围与样本 | 行业背景不冒充项目结果；未知值不进入排序；职业准入可回到国家目录。 |
| 方案与行动页 | 比较分组、理由、风险、待办、官方链接 | 只使用四类候选分组；不含录取承诺；每个关键理由可解释或标为待核验。 |
| 纠错页 | 字段、建议、官方证据、处理状态 | 用户能查看受理状态；未经审核的投稿不进入排序。 |

### 5.3 无障碍、信任与体验底线

- 信息状态不只依赖颜色；证据、过期和待核验有文字和图标说明。
- 对比表可键盘操作，关键字段可在窄屏阅读；移动端优先服务提醒、方案查看和官方跳转。
- 任何 AI 方案、推广内容和合作结果都有清楚的身份与边界说明。
- 用户操作失败时仅显示可理解的操作建议，绝不展示数据库、模型或内部服务诊断信息。

## 6. 数据与可信机制

### 6.1 核心数据模型

目录与覆盖：

`CoverageManifest → 目录版本 → TaxonomyNode（可变层级与父节点） → 招生单位 → 培养单位 → 年度招生项目`

年度项目可以直接挂到一级学科、专业学位类别、专业领域或院校自设节点。`TaxonomyMapping` 必须区分 `mapped`、`ambiguous`、`unmapped` 和 `institution_specific`，不能强制所有六位代码落到唯一标准节点。

证据与决策不是线性一对一。内容寻址的 `RawBlob` 与每次访问的 `SourceFetch` 分离；`SourceDocumentRevision → EvidenceClaimRevision → ReviewDecision → PublicationEvent` 形成追加式证据链。`RuleSetRevision`、`RuleEvidenceUsage`、`ComparisonRuleUsage`、`ComparisonEvidenceUsage` 以及可选 AI 解释的 `RecommendationRuleUsage`/`RecommendationEvidenceUsage` 保存多对多引用；`OutboxEvent`、`JobExecution` 和幂等键保证纠错、发布、重算和通知只执行一次。

职业结果主链：

`指标定义 MetricDefinition → 证据范围 EvidenceScope → 职业结果证据 CareerOutcomeEvidence → 职业 Occupation`

运营主链：

`CoverageManifest → 数据覆盖 DataCoverage → 纠错案件 CorrectionCase → 审核与发布记录 → 不可变 AuditEvent`

每一条 `EvidenceClaimRevision` 只表达一个可验证事实，至少包含：`年度招生项目、字段、规范化值、原文值、适用范围与生效日期、来源文档、原文定位、来源等级、发布日期、抓取时间、人工核验时间、审核人、证据快照哈希、转换规则、下次复核事件、状态`。规则只能引用已发布的证据声明。`EligibilityCheck` 保存规则版本、适用性、输入、结果、原因和证据引用；只有冻结范围内的适用规则全集已发布且全部通过时才返回 `eligible_known`，未知、冲突或适用性不明统一为 `needs_confirmation`。

`DecisionSnapshot` 必须选择 `shortlist_ready`、`no_suitable_offering`、`awaiting_official_information`、`postpone_application` 之一，并保存对应的保留/排除/延后项目、用户确认理由、关键未知、下一步、复查日期、`ComparisonRun`、事实/规则/证据版本和确定性结果哈希。快照不存放或展示录取概率、综合成功率或标量置信度；只显示逐字段证据状态。资格、分组和排序必须在相同快照下确定性重放；可选 LLM 文案不要求逐字重现，只保存原响应、输入快照、提示模板版本和校验结果。

首批结构化字段为：目录版本、门类、一级学科/专业学位类别、六位专业/领域与方向、培养单位、学位类型、学习方式、地区与校区、报考资格、初试科目组合、总计划/推免/统考/专项/联合培养、学制、学费、住宿、奖助、复试/材料要求、关键日期和官方联系入口。职业结果字段必须另带人群、届次、观察窗口、定义、样本、响应率和范围匹配状态。

### 6.2 来源规则

| 等级 | 可用来源 | 用途 |
| --- | --- | --- |
| 一级 | 教育主管部门、招生单位研究生院/招生网公告 | 进入筛选与关键事实展示。 |
| 二级 | 院系、课题组、导师官方主页 | 补充机构资料，不能覆盖一级年度招生事实。 |
| 三级 | 用户投稿、论坛、媒体 | 仅作待核验线索，不能进入排序或事实卡。 |

关键字段（资格、截止日、费用、学习方式、招生计划、复试规则）变更需要人工复核；当来源过期或有冲突时，暂停将其用于自动结论。更新采用**年度基线＋发布/变更事件触发**：招生简章、复试录取、调剂等分阶段发布，未发布字段显示“待发布”，不以往年数据推断。

### 6.3 数据采集与审核运营

本节新增硬门槛并优先于下文的一般采集要求：每个真实 `DataSource` 必须记录权利基础、允许采集和公开展示的路径/字段、下架入口及责任人。robots 或技术可访问性不等于拥有复制、加工或展示权；原始快照进入隔离存储，用户页只显示必要、可授权且已去标识化的证据摘录和定位。不具备自动采集或公开展示依据时，只保存经授权文件或官方链接。

真实来源接入前，每个 `DataSource` 必须记录责任人、允许采集的路径、robots/使用条款检查结果、限速、更新事件、失败阈值和人工联系入口。采集不得绕过登录、验证码、访问控制或网站明确禁止的技术措施；对不适合自动采集的来源，改为人工录入并保存原始文件。自动化访问还必须评估对网络服务的影响并遵守数据安全要求。[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)

发布流程固定为：

1. 获取原始文档并按内容哈希保存不可变快照；失败时记录脱敏错误，不覆盖旧版本。
2. 解析成候选证据声明；解析结果默认不可见，也不能参与规则。
3. 机器校验年度、项目映射、字段类型、重复与明显冲突。
4. 人工逐项对照原文，确认适用范围和原文定位。
5. 发布证据及规则影响范围；对受影响的已保存方案重新计算。
6. 记录变更、通知受影响用户；旧版本继续可审计但不作为当前结论。

冲突处理采用“更高等级、适用范围更精确、发布日期更新”作为排序线索，但不得自动覆盖。涉及资格、科目、费用、截止日、学习方式或招生计划的冲突必须人工裁决；裁决前状态为 `needs_confirmation`。用户纠错必须形成 `CorrectionCase`，记录证据、处理人、结论、理由和通知状态。

### 6.4 质量指标与发布门槛

审计开始前冻结 `CoverageManifest(target_year, scope, annual_offering_ids)`，覆盖率分母始终使用该清单。下文“已发布年度招生项目”只表示可参与结论的状态，不得用作缩小覆盖率分母；项目退出必须形成新版本并保留原因，不能回写历史分母。

| 指标 | 计算口径 | 邀请制发布门槛 |
| --- | --- | --- |
| 项目纳入覆盖率 | 已建立并核对项目实体的年度项目数 ÷ 冻结清单项目数 | 100% |
| 当前一手证据覆盖率 | 已有当前年度一级来源的 P0 字段数 ÷ 冻结清单应有 P0 字段数 | 100%；`pending_publication` 单独报告，不计入当前证据 |
| 待发布率 | 正式文件尚未发布的 P0 字段数 ÷ 冻结清单应有 P0 字段数 | 单独披露；任何相关肯定结论为 0 |
| P0 字段状态透明率 | 已有当前年度一级来源、待发布、待核验、冲突或过期等明确状态的 P0 字段数 ÷ 冻结清单应有 P0 字段数 | 100%；该指标不等于当前证据覆盖率 |
| P0 字段双人复核率 | 已由录入者之外的复核人确认且可发布的 P0 字段数 ÷ 冻结清单应有 P0 字段数 | 100%；`pending_publication` 只能作为 0 计入分子，不能缩小分母 |
| S0/S1 严重错误 | 对试点全部项目逐字段审计发现的 S0/S1 数量 | 0；出现即暂停相关结论并复盘 |
| 来源可用率 | 每周检查中成功打开且内容匹配的当前来源链接数 ÷ 当前来源链接数 | 发布时 100%，运行期不低于 98% |
| 纠错处理时长 | 从受理到给出可审计结论的工作日 | 中位数不超过 2 个工作日，95 分位不超过 5 个工作日 |
| 变更生效时长 | 人工批准证据变更至完成受影响方案重算 | 不超过 1 个工作日 |
| 可重放率 | 抽检方案中能用保存的事实、规则和证据版本重现分组及理由的方案数 ÷ 抽检方案数 | 100% |

P0 字段是资格、初试科目、学习方式、费用、关键日期及直接影响用户能否报考的招生计划说明。错误等级：S0 为导致错误报考、错过截止日、资金损失或虚假录取承诺；S1 为 P0 字段错误但尚无已知用户损害；S2 为其他决策字段错误；S3 为不改变事实含义的展示问题。“严重错误为零”只指完成上述全量试点审计后的已知结果，不代表对未知事实作绝对保证。

中国研究生招生信息网和招生单位是目录与年度信息的关键参考，但用户应始终回到招生单位确认，平台不替代官方通知。[研招网硕士目录](https://yz.chsi.com.cn/zsml/) [教育部研究生教育学科专业目录](https://www.moe.gov.cn/srcsite/A22/moe_833/202209/t20220914_660828.html)

### 6.5 职业结果与统计范围合同

范围判定底层分别保存实体、人群、时间、指标定义和学习方式匹配，再聚合为前台三态。“学硕/专硕混合样本不能比较”仅指未分组、届次/观察窗/指标定义不同或无法识别分母的样本；同源同届、定义一致且分组充分的样本可以比较。

“毕业去向落实率”必须拆分直接就业、升学及其他去向；工资必须标明应届起薪、毕业后收入或行业全体从业者平均。任何结果指标至少包含教育层次、学位类型、学习方式、目录版本、专业/学校/项目范围、毕业届次、观察窗口、地区、行业、统计量、分子、分母、样本量、响应率、来源和证据等级。

聚合范围只允许 `exact_match`、`broader_context`、`incompatible`。前者可作为项目直接历史证据；第二类只能作为学校、学科、全国或行业背景；第三类不得进入项目卡、比较或排序。本科结果不能冒充硕士结果，行业平均工资不能冒充应届起薪。未按学位类型分组或分组口径、届次、观察窗不同的样本不得比较；同源同届、定义一致且分组充分的样本可以比较。未知值保持未知。

产品不建立专业“社会地位分”。职业名称映射国家职业分类，准入要求映射国家职业资格目录；分别展示资格、职业/行业/单位/地区分布、专业相关度、稳定性、工作强度、收入波动和深造空间。

## 7. LLM 定制化方案设计

### 7.1 LLM 做什么，不做什么

| 层 | 职责 | 禁止行为 |
| --- | --- | --- |
| 数据层 | 保存官方来源、字段、快照和审核状态 | 依据网页或往年信息填补未知字段。 |
| 规则/匹配层 | 硬约束检查、加权排序、候选梯度与规则版本 | 生成招生事实、宣称录取概率。 |
| LLM 层 | 意图识别、对话追问、结构化抽取、基于证据解释 | 直接访问任意网页/SQL、自由编造项目事实。 |
| 人工层 | 审核来源、处理例外、复核高风险方案 | 代替平台持续手工编造个性化结论。 |

### 7.2 定制方案的输出合同

每份方案应包含：

- 已确认事实和仍待确认的问题；
- 候选集与每项硬约束检查结果；
- 适配理由及对应证据编号；
- 信息缺口、风险和“以招生单位最新通知为准”的提示；
- 可执行的下一步、日期和官方链接；
- 生成时间、使用的数据版本与模型版本。

模型输出严格遵守 JSON Schema；服务端验证候选、字段和 `evidence_id` 后才渲染。没有证据的事实必须返回“待核验”，而不是自然语言补全。排序与硬约束必须逐项解释、版本化且可复现；提供非个性化排序或关闭个性化的入口。没有录取概率不等于自动免除算法和生成式 AI 的适用性评估。

偏好排序只对 `eligible_known` 项目生效。每个偏好先转换为 `满足、部分满足、不满足、未知`，再按用户确认的权重生成比较顺序；未知值不按零分惩罚，而是单独显示信息缺口。相同偏好结果保持真实并列；证据完整度只影响可信状态，不作为适配优胜条件。页面可按项目名称做稳定的非语义渲染顺序。系统展示分项理由，不展示容易被误读为录取概率的百分制总分。`needs_confirmation` 与 `ineligible_known` 不参加偏好排序。

### 7.3 安全、隐私与评测

- 初期只收目标年度、路径、方向、背景摘要、预算区间与地域偏好；默认不收身份证、精确地址、银行卡、健康/心理信息、完整成绩单或证件图片。
- 对话原文、结构化偏好、身份账户和审计日志分层存储；默认短期保留原文，不用真实对话训练模型。
- 用户可查看、更正、导出和删除与其关联的账户、对话、研究、分析事件、支持记录、订单及设备/登录数据（依法必须留存的除外）；涉及自动化决策时提供解释、人工复核和非个性化选择。
- 上线前建立对抗集：过期简章、同名专业、跨专业、同等学力、错别字、提示词注入和不存在项目；同时测量用户是否正确理解“匹配不等于录取可能性”。
- 严重错误为零才可进入公开试点：错报资格、截止日、费用、科目或作出录取承诺。

邀请制试点采用以下可执行默认值；公开上线前可依据书面评估收紧，但不得静默放宽：

- 原始对话默认保留 30 天后自动删除；结构化偏好在账户存续期间保存，用户可随时删除。
- 用户发起删除后立即停止使用相关数据，主要业务库在 7 天内删除；备份中的副本在 30 天内随轮换清除。依法必须留存的记录单独隔离并向用户说明类别与期限。
- 模型供应商不得使用输入训练通用模型；上线前记录供应商、处理地区、数据保留、分包商和故障处理约定。
- AI 内容在页面、导出和分享中提供适用的显式标识，并在文件/元数据中实现适用的隐式标识；提供投诉、举报、纠错、人工复核和账户删除入口，并记录受理状态。
- 模型超时、预算耗尽、证据校验失败或供应商不可用时，降级为已核验项目比较与待核验清单；不得把自由生成文本作为兜底事实。
- 进入个性化方案前只询问“是否已满 18 周岁”，不收集生日或身份证号；确认未满 18 周岁或拒绝确认的用户只能使用非个性化公开信息。后续若覆盖未成年人，必须先完成单独的监护、最小必要和算法保护设计。

公开上线前必须完成服务协议、隐私政策、模型与其他供应商/分包商数据处理清单、个人信息流图、跨境与自动化决策适用性评估、删除演练、投诉机制、AI 显式/隐式标识和安全事件响应演练。服务协议应明确平台不是招生单位，用户必须以官方最新通知和招生单位确认为准。网络日志、业务审计、行为分析、对话、订单和证据制品分别定义目的与期限；网络日志遵守适用法定最低期限，不能用统一“180 天”覆盖全部类别。

《个人信息保护法》对敏感个人信息、自动化决策、最小必要和透明度设有要求；算法推荐和面向公众的生成式 AI 还存在相应主体责任、透明度和备案/评估边界，需在公开上线前获得属地专业意见。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm) [算法推荐管理规定](https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm) [生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

### 7.4 与现有工程的衔接

现有 Next.js、Django、PostgreSQL、对象存储、Celery 和 `ingestion` 模块足以支持首期，无需先拆微服务或引入独立向量数据库。新增边界建议为：

`catalog`（年度项目与证据） → `advising`（偏好、规则、方案） → `llm_gateway`（模型调用、预算、审计与降级）。

采集服务继续保存原始快照、来源 URL 与内容哈希；当模型不可用、证据过期或规则无结果时，产品降级为“已核验项目比较”，不能输出看似完整的 AI 结论。

## 8. 商业化与合规路线

### 8.1 结论

**个人收款码、公开信息搬运和早期信息流广告都不是合适的核心商业模式。首选长期方向是按目标入学年度售卖的报考季软件决策包；在软件付费尚未验证前，先用标准化人工结果验证价值，不把人工收入当作软件成立。**

免费层必须让用户完成一次安全决策闭环：资格三态、影响结论的事实与未知、官方来源、基础对比、决策快照，以及 S0/S1 更正或资格失效提醒不得被付费墙遮挡。付费只销售跨时间便利和增量能力，例如更多历史版本、深度对比、持续监控、协作、批量导出或更高服务 SLA；不得销售“看见真相”的权限。

建议顺序是：

1. 在完成主体、税务、商户收款与服务规则准备后，做标准化人工“选校诊断包”，只验证“用户是否愿意为有证据的决策结果付费”。
2. 在邀请制工具中单独测试目标年度“报考季决策包”：深度比较、保存方案、证据更新与提醒。权益、价格、渠道和退款条件固定后再比较 cohort；人工咨询收入不得直接证明软件成立。
3. 只有用户在没有一对一代查时真实付款，并在预登记的关键报考节点查看更新、修改候选或完成行动，才继续测试更新服务或续费；仅当该节点尚未到达时，使用 D30 作为代理观察，不能用 D30 单独否定低频价值。
4. 只有识别出明确的 B 端购买角色、工作任务、可合法使用的数据范围和足够样本量后，才试售聚合研究报告；不售卖个人线索。
5. 在自然排序、用户信任和数据治理成熟后，才考虑清晰标注、与自然推荐完全隔离的赞助位；广告不是第一桶金。

人工服务与软件产品必须分别核算：人工服务记录获客、工时、返工、退款、毛利和用户实际动作；软件记录激活、关键节点复访、更新查看、付费和支持成本。如果只有高强度人工介入才能产生价值，应判定为服务业务，不得用其收入推导软件可以规模化。每个数据运营任务还记录录入、复核、返工和变更工时，用“项目 × P0 字段 × 发布/变更事件”评估是否随规模近似线性增长。

盈利报告采用四层口径且不得合并：

1. `交付贡献毛利 = 实收 − 退款 − 支付费 − 直接复核/支持 − 模型/通知等可变成本`；
2. `扣获客后贡献 = 交付贡献毛利 − 可归因付费获客`；
3. `年度经营利润 = 扣获客后贡献合计 − 人员、合规、基础设施等固定成本`；
4. 现金流单独报告回款、退款时点和预付/应付。`有效激活成本` 不得命名为付费 CAC。

软件可持续盈利的必要条件是年度汇总的扣获客后贡献大于分配到该产品的人员、合规、基础设施等年度固定成本；不能用“收入覆盖固定成本”替代利润判断。每次扩大固定投入还必须提交未来 12 个月逐月现金流，并在承诺新增支出后保留不少于 6 个月已承诺支出的可用资金；“6 个月”是当前风险偏好，不是行业定律。

### 8.2 各模式比较

| 模式 | 早期价值 | 现金流 | 风险与条件 | 决策 |
| --- | --- | --- | --- | --- |
| 标准化人工咨询 | 强，高信任 | 单笔快 | 需主体、商户支付、服务/退款规则；不承诺录取 | 首选验证模式。 |
| 报考季软件决策包 | 与年度决策周期匹配 | 单季一次性为主 | 必须证明用户在无一对一代查时仍付款、复访且贡献毛利为正 | 核心软件商业假设。 |
| 更新提醒/长期会员 | 对变更频繁用户有潜力 | 可能复购 | 季节性强，必须用更新查看和续费行为验证 | 决策包成立后再测。 |
| 匿名 B 端研究报告 | 尚未验证 | 客单可能较高 | 先确认购买方、用途、样本充分性；不能转卖线索 | 满足前置条件后试售，不与 C 端同时强推。 |
| 会员与工具订阅 | 长期潜力 | 可复购 | 必须独立验证软件价值；自营线上服务、数据和许可边界先核清 | 价值与合规双门槛通过后推进。 |
| 广告/信息流 | 容易伤害信任 | 依赖流量 | 必须可识别、资料留存、与排序隔离 | 最后考虑。 |
| 个人收款码 | 无新增价值 | 表面快 | 团队经营下不具备订单、退款、对账与开票闭环 | 团队不采用，统一走经营主体商户/对公结算。 |

对具有明显经营特征的个人，人民银行相关规则要求支付机构提供特约商户收款码；本团队把“不使用员工个人账户或个人码收取经营款”作为可审计的经营控制，而不是把所有个人收款码笼统表述为违法。[人民银行支付受理终端管理通知](https://fgw.sh.gov.cn/cmsres/9e/9e0713cc8c94493bb1eecdc45a692754/6ba9ebf6852589739070044c401c32a6.pdf)

### 8.3 当前无服务器、无备案时的边界

- 封闭验证只限于书面界定的内部或受控测试；只要向外部个人提供服务，就按面向公众服务进行预评估。它不能被视为自动免除互联网服务、数据、消费者权益或生成式 AI 要求。
- 不用“私聊付费资料”“群内会员库”规避持续性付费信息服务的性质。
- 在启动面向公众的网站、APP 或小程序之前，明确接入、主体和备案路径；付费会员不是“有备案即可上线”。一旦含有收费、交易撮合、机构入驻或代收款，须向属地通信管理部门和律师获取具体业务的书面定性。
- 不因为使用境外服务器或境外模型而假定可免除面向中国境内用户的数据、内容和消费者保护义务。

现行规则区分经营性与非经营性互联网信息服务，并规定相应许可/备案要求；APP 也适用备案管理。具体许可定性须由属地主管部门和专业法律意见确认，本文不构成法律意见。[互联网信息服务管理办法](https://sdca.miit.gov.cn/zwgk/fgbz/art/2026/art_fea940f81f1d423e87101adf147ab979.html) [非经营性互联网信息服务备案管理办法](https://sdca.miit.gov.cn/zwgk/fgbz/art/2026/art_f4a017d7fcb741238bdbdab836a60431.html) [工信部 APP 备案通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html)

### 8.4 商业与信任护栏

- 所有付费合作、赞助、竞价结果显著标识“广告/推广/赞助”，并保存审核与投放记录。
- 付费状态永远不改变自然推荐排序；若有合作项目，同时披露关系与非合作替代选项。
- 不使用“保上岸”“保录取”“内部名额”“官方指定”等宣传。
- 对用户资料共享给合作方，必须先明确接收方、目的、种类与方式并取得适当同意；默认不共享。
- 机构关系不得影响项目收录、更新速度、证据展示位置或更正优先级；研究参与者或顾问的利益冲突必须披露并回避相关审核。
- 上线付款前冻结权益、价格、交付边界、服务中断补偿、退款触发和平台/用户责任矩阵；广告、用户评价或案例用于营销前单独完成合规审查。

互联网广告需可识别，教育广告不得对升学、考试或学位结果作明示或暗示保证。[互联网广告管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html) [广告法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_5474cf75173c45d6a0379730fb4e8d97.html)

## 9. 获客与增长策略

### 9.1 先验证，再买量

第一目标不是“做大流量”，而是证明用户会因一份带来源、能解释的结果单，完成真实决策动作。内容、社群先行和搜索买量后置是**待验证的增长假设**，不是普遍成立的因果规律。北极星事件定义为：

`提交选择标准 → 查看方案 → 打开官方来源或保存/比较至少一个候选`

注册不是北极星指标，曝光也不是获客成功。产品价值不能只由点击定义；任务回放还要证明用户对资格、名额分母、总成本和职业证据适用范围的正确理解提高，虚假确信不增加。

### 9.2 分阶段增长验证路线

下表中的访谈数、内容数和社群数是学习预算，不是统计显著性的证明。每个阶段按继续门槛而不是日历自动升级；未达到门槛时应缩小范围、修正产品或停止假设，而不是延长投放。

| 阶段 | 目标 | 学习预算 | 继续门槛 |
| --- | --- | --- | --- |
| 第 0 阶段 | 找到真实任务 | 访谈同一细分人群最多 15 人；人工交付最多 5 份结果单 | 至少 5 位非团队成员指出结果改变了一个候选、核验问题或下一步动作；问题模式开始重复。 |
| 第 1 阶段 | 验证产品承诺 | 发布最多 9 个窄主题内容，邀请最多 30 位非熟人进入 beta | 至少 10 位完成有效激活；其中至少 5 位在访谈中正确解释证据与资格三态。 |
| 第 2 阶段 | 验证复用与更新价值 | 最多进入 3 个校园/垂直社群；对已激活用户跟踪 30 天 | 至少 30% 的已激活用户在 30 天内修改清单、查看更新或完成一项行动；不得只以再次登录计回访。 |
| 第 3 阶段 | 验证可重复触达 | 仅对高意图搜索词进行一个预登记的小额实验 | 付费 cohort 的有效激活率、来源打开率和预登记关键节点行为不低于自然 cohort 的 80%，节点未到时才比较 D30 代理，且投诉率未恶化。 |

### 9.3 渠道策略

- **内容**：小红书、B 站、抖音、知乎等内容只讲一个真实问题，例如“如何核验某专业当年招生条件”；每篇都指向有来源的结果页或访谈入口。
- **搜索**：先做窄主题、强时效、含官方来源的资料页；成熟后才以小额搜索广告测试显性需求。
- **校园与社群**：与学生组织、校友和垂直社群共建核验表，而不是购买群成员名单或考研线索。
- **协作分享**：分享只读比较卡给同学、家长或辅导员；不得泄露成绩、联系方式和完整偏好。
- **买量**：每个词/创意只设学习预算和停止条件。试验前登记目标人群、样本、成功阈值与停止条件；若达到预定学习样本仍没有有效激活，停止该组合，先修产品承诺或落地页，不加预算。

### 9.4 测量与止损

所有入口统一带 `source、medium、campaign、content、keyword、variant、partner`。服务端记录：

`landing_view、match_start、match_submit、result_view、source_open、save_or_compare、return_d7、feedback_submit`

补充记录：`criteria_revised、project_removed、official_question_created、action_completed、result_update_view、return_d30、correction_resolved`。`return_d7` 只用于观察短期体验，阶段性留存以 30 日内发生上述至少一个真实决策事件为准。

核心口径：

`有效激活成本 = 可归因总支出 ÷ 经核验有效激活人数`

在有真实留存、付费和交付成本前，不宣称可规模化的获客成本。买量只用于购买学习，不用于掩盖产品价值不足。

## 10. 验证矩阵：每项需求如何证明

| 待验证假设 | 对照或证据 | 通过信号 | 不通过时的动作 |
| --- | --- | --- | --- |
| 用户需要年度项目比较，而不是学校榜单 | 真实任务回放，对比榜单原型与证据原型 | 用户能用字段和来源解释取舍 | 调整首页叙事与筛选入口。 |

| LLM 对话能降低填写负担 | 对照表单与对话完成率、遗漏率、满意度 | 更少追问但事实卡更完整 | 缩短访谈，减少低价值字段。 |

| 用户愿意为人工结果付费 | 以实际价格售卖标准化人工诊断包 | 非熟人真实付款，且交付工时、退款和毛利可核算 | 不扩大人工服务，先重做价值与交付。 |
| 用户愿意为软件持续价值付费 | 与人工服务分开，以实际价格测试更新、证据对比或提醒订阅 | 用户在无一对一代查的情况下真实付款，并在预登记关键报考节点使用更新或行动功能；节点未到时只记录 D30 代理 | 不用人工收入证明会员成立。 |
| 报考季软件可以盈利 | 固定权益/价格的付费 cohort，完整记录退款、支付、复核、支持、模型、通知、获客和分配固定成本 | 年度扣获客后贡献大于分配固定成本，12 个月逐月现金流不触发当前 6 个月承诺支出流动性红线；人工代查工时不随用户线性增长 | 收窄权益、提高自动化或停止软件盈利假设。 |
| B 端存在真实任务 | 访谈明确角色并出示不含个人线索的样例报告 | 购买方能说明决策用途、采购预算与合法数据需求，并愿意签署试点合同 | 暂停 B 端路线，不凭想象生产报告。 |
| 自然渠道可带来目标用户 | 内容/社群按来源观察有效激活与回访 | 目标用户完成结果单，不只收藏 | 停止泛内容，改细分人群或承诺。 |
| 买量可以扩大而非稀释质量 | 自然与付费 cohort 对照 | 付费用户的来源查看、保存、回访不显著变差 | 停止扩大投放。 |

## 11. 指标体系

| 维度 | 指标 | 定义 |
| --- | --- | --- |
| 用户价值 | 可信候选清单完成率 | 在一次会话中保存或比较至少 2 个候选，打开至少 1 个官方来源并生成至少 1 个下一步动作的用户 ÷ 提交选择标准的用户。 |
| 用户价值 | 决策正确与伤害 | 任务回放中资格、名额分母、总成本和证据范围的正确率、虚假确信率、S0/S1 误导与用户报告伤害；同时记录“无合适项目/等待信息/暂缓考研”。 |
| 决策效率 | 首份可用清单耗时 | 从 `match_submit` 到展示至少 2 个有证据候选和 1 个行动项的中位时长；同时报告 95 分位。 |
| 数据可信 | 证据覆盖、复核、错误、链接、纠错和重放 | 全部严格采用 6.4 的分母、等级和门槛，不另造口径。 |
| 留存 | 关键报考节点行为率与 D30 代理 | 在 cohort 预登记的材料发布、预报名、正式报名等关键节点窗口发生 `criteria_revised`、`result_update_view`、`action_completed` 或 `correction_resolved` 的用户率；节点尚未到达时另报 30 天代理，不混成同一指标。 |
| 商业 | 人工服务与软件分别核算 | 分别报告真实付款转化、退款、直接工时/支持成本、支付费用和贡献毛利；不得合并。 |
| 商业 | 四层盈利口径 | 分别报告交付贡献毛利、扣可归因付费获客后的贡献、年度经营利润和现金流；按自然/付费渠道、目标年度和产品类型分 cohort。 |
| 安全 | AI 与隐私发布门槛 | 对抗集中 S0/S1 为 0；删除流程抽检成功率 100%；无有效证据 ID 的事实渲染数为 0。 |

所有比率同时展示分子、分母、观察窗口和 cohort 来源；样本不足 30 时只作探索性观察，不对外宣称稳定转化或可规模化。投诉率按“有效投诉用户数 ÷ 获得方案的用户数”计算，并按数据错误、误导表达、隐私和服务交付分类。

## 12. 分期路线、容量假设与投资门槛

排期按“一名全职开发者兼产品负责人，另有兼职数据复核人员”的保守容量制定。若没有独立数据复核人员，不得把同一人的录入和自审算作双人复核；项目数量应继续缩小。每一阶段只有达到出口门槛才进入下一阶段，时间只是估算，不是上线承诺。

### 阶段 A：问题与证据原型，预计 1–2 周

- 使用 [`pilot-scope-2027-v1`](research/pilot-scope-2027-v1.md) 中冻结的 3 个计划项目验证真实待发布链路；用隔离的 `synthetic` 或 `reference_year=2026` 测试规则和对抗性合成档案覆盖三态、跨专业、同等学力和信息冲突。测试 fixture 不得进入生产 API、覆盖率或 2027 用户结论，非全日制留到独立范围验证。
- 本地或封闭环境；合成用户档案；不公开收费、不收集个人材料。
- 外部访谈前先完成研究告知、同意、退出、补偿、去标识化和保留方案；按 [`free-alternative-protocol-v1`](research/validation-protocol-v1.md) 完成最多 15 次同一微人群访谈和任务回放，并形成证据字段模板、资格三态规则草模和人工结果单。
- **出口门槛**：问题模式开始重复；用户能用结果减少一个关键错误或形成可解释决策；3 个计划项目跑通来源、复核、待发布、比较、纠错与幂等重算，隔离 fixture 跑通资格三态。该门槛不允许把未发布的 2027 资格标成已知。

### 阶段 B：数据运营与规则闭环，预计 3–6 周

- 冻结 2027 年 10 个年度招生项目；优先人工录入和复核，自动采集只用于已完成权利、条款、安全和限速评估的站点。
- 完成 `CoverageManifest`、来源抓取、证据声明、规则全集、决策快照、纠错案件、不可变审计和确定性重放最小闭环。
- 完成资格三态、比较分组、来源冲突、变更重算和降级演练。
- **出口门槛**：达到 6.4 的全部数据门槛；对抗集 S0/S1 为 0；任何方案可重放。

### 阶段 C：邀请制产品，预计 7–12 周

- 项目发现、详情、对比、方案、行动清单和纠错页形成纵向链路；不以扩大项目数替代体验闭环。
- 最多邀请 30 位非熟人；先验证无 LLM 的规则与证据链。启用外部 AI 前完成供应商、数据地域/保留/分包、显式与隐式标识及适用备案/登记的书面判断；所有 AI 方案经过证据校验，高风险结果人工抽检。
- 完成数据删除、供应商降级、来源失效和用户纠错演练。
- **出口门槛**：至少 10 位有效激活，至少 5 位正确理解资格三态和“比较优先级不等于录取概率”；每位付费验证用户需在预登记的关键报考节点发生真实更新/行动，若该节点尚未到达才使用 D30 作为代理观察。

### 阶段 D：公开小流量，最快在第 13 周后且合规条件完成

- 托管服务、主体、备案/许可边界、隐私规则、模型供应商、AI 标识和数据流完成书面核查。
- 通过发布清单中的数据、AI、隐私、运维、支持和商业门槛；准备暂停开关和事件响应责任人。
- 小额搜索投放只验证渠道质量；先上线账号同步、更新提醒和受控的协作分享。

### 扩展阶段

- 首期连续两个更新事件周期满足数据 SLA，且当前项目覆盖不依赖不可持续的人工救火后，才扩大专业和院校范围。
- 按独立规则包扩展推免、国内博士、港澳和海外申请；每条路线重新做数据、资格、合规和用户验证，不能复用“统考适用”的结论。
- 只有导师/课题组字段可稳定回源且招生状态可维护时，才上线导师研究方向匹配。
- Web 的邀请制体验达到门槛且存在明确移动场景后，才创建 Expo 产品页；优先迁移提醒、方案查看和官方跳转，共享领域模型、设计令牌和生成客户端。

### 12.1 公开发布 Go/No-Go 清单

每个门槛必须形成不可变的 `GateDecision`，状态只能为 `pending`、`go`、`conditional_go`、`not_applicable_with_rationale` 或 `no_go`。记录至少包含能力、精确范围、部署指纹、审批人、证据引用、决定/到期时间、条件和被替代决定。只有当前决定为 `go`，或 `conditional_go` 的条件已核验完成，或有签署理由的 `not_applicable_with_rationale`，才允许相同能力和部署指纹上线；`pending`、`no_go`、过期决定或部署指纹变化均阻断。

| 门槛 | Go 的证据 |
| --- | --- |
| 产品价值 | 邀请制有效激活达到阶段 C 门槛，预登记的关键报考节点行为（节点未到时才用 D30 代理）和用户理解测试通过。 |
| 数据质量 | 6.4 的全部指标通过，并完成一次真实来源变更演练。 |
| AI 安全 | 对抗集 S0/S1 为 0，证据校验、超时、预算耗尽和供应商故障均能降级。 |
| 隐私与用户权利 | 服务协议、隐私政策、数据流、导出、删除、投诉和事件响应完成实测。 |
| 运维 | 生产监控、备份恢复、审计日志、最小权限、告警联系人和暂停开关完成演练。 |
| 合规 | 主体、网站/APP 备案及实际业务许可边界、模型和数据处理获得与上线形态一致的书面核查。 |
| 支持能力 | 数据纠错与用户投诉有负责人，能在承诺时限内处理当前邀请规模两倍的工单。 |
| 商业诚信 | 收款、合同/订单、退款、对账和开票闭环已建立；付费合作与自然排序隔离。 |

上述总门槛不能替代分阶段阻断：外部用户研究前通过研究合规；真实来源采集/展示前通过来源权利与安全评估；外部 AI 前通过供应商、数据和标识评估；公开 Web/APP 前通过主体、备案/许可和安全评估；支付或广告前通过订单、退款、消费者权益、广告和税务评估。任一 `GateDecision` 只放行其精确能力和部署指纹，不自动放行后续阶段或另一供应商、地域或域名。

## 13. 主要风险与暂停条件

| 风险 | 暂停条件 | 缓解措施 |
| --- | --- | --- |
| 数据过期或错误 | 出现严重字段错误或来源冲突未处理 | 暂停相关项目自动推荐，人工复核。 |
| 来源采集不被允许或干扰对方服务 | robots/条款不允许、触发访问控制或对方提出异议 | 立即停采，保留审计记录，改为授权、人工录入或移除来源。 |
| LLM 幻觉 | 伪造来源、错报资格/日期/费用 | 强制证据 ID、Schema 校验、降级为比较页。 |
| 数据运营能力不足 | 纠错、冲突或变更连续两周超过 SLA | 冻结扩容，缩小项目范围并增加复核能力。 |
| 商业利益污染推荐 | 付费项目影响自然排序 | 排序与商业系统物理隔离，公开披露。 |
| 隐私越界 | 收集非必要材料、无法删除 | 最小化收集、数据流图、访问审计和删除测试。 |
| 流量虚高无价值 | 注册/曝光高但有效激活低 | 停止投放，回到用户访谈与承诺测试。 |
| 合规边界不清 | 自营公开/付费功能拟上线但无书面意见 | 不上线，先完成主体、备案与法律核查。 |
| 单人排期失真 | 阶段门槛未通过但仍按日期扩功能 | 按出口门槛重排，只保留一条可验证纵向链路。 |

## 14. 近期决策清单

1. 严格按 `pilot-scope-2027-v1` 已冻结的北京、三所院校、全日制统考和候选收敛阶段招募；只验证该范围是否成立，不在实验中继续改分母。
2. 先用冻结清单中的 3 个计划项目跑通完整工程闭环；邀请用户前按同一清单审计 10 个项目，通过运营容量门槛后再决定是否创建新版本扩容。
3. 按 `docs/product-requirements.md` 的 P0 需求做不接真实个人材料的纵向链路。
4. 建立来源评估、人工复核、冲突裁决、纠错和方案重放流程。
5. 首个邀请制保持 LLM 关闭；只有准备启用外部 AI 时才建立 LLM 对抗评测集，并按 S0–S3 和 `GateDecision` 执行阻断。
6. 分开验证人工诊断与报考季软件包付费意愿；准备商户支付、权益矩阵、交付/退款责任和服务规则，不用个人收款码。
7. 用可归因内容与校园社群验证有效激活和预登记关键报考节点行为；节点未到时只把 D30 当代理，未通过前不买量。
8. 在公开运营、线上收费、接入境外模型/数据服务或机构合作前，取得属地通信管理与专业法律意见。
9. 用固定权益和价格分别验证人工诊断包与报考季软件决策包；真实付款、关键节点行为和正贡献只允许进入下一步核算，只有年度扣获客后贡献覆盖分配固定成本且 12 个月现金流满足流动性策略后才扩大固定投入。
