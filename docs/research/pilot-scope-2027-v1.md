# GradMatch 2027 北京计算机方向试点范围 V1

**状态：冻结的学习范围｜版本：`pilot-scope-2027-v1`｜冻结日期：2026-09-01**

## 1. 这份清单解决什么问题

本文件冻结首个纵向试点的人群、地域、阶段和项目分母，避免在开发或实验过程中通过增加、删除项目改变覆盖率。它是学习范围，不是市场规模判断，也不表示 2027 年招生事实已经发布。

2027 年正式目录尚未发布。下列 `annual_offering_id` 是计划验证的年度项目身份；所有招生事实初始状态均为 `pending_publication`。2026 年官方材料只用于证明这些院校/代码组合值得作为候选和设计数据结构，不得复制为 2027 当前事实。若 2027 官方目录与计划身份不一致，关闭对应计划实体、记录原因并创建新的 manifest 版本，不能改写 V1。

## 2. 冻结的目标用户

- 目标入学年度：2027。
- 报考路径：全国统一考试；首轮不含推免、单独考试、专项计划和军队系统。
- 地域：把北京作为当前硬约束；首轮不代表全国用户。
- 学习方式：全日制。
- 方向：计算机学术学位或电子信息专硕中的计算机相关领域。
- 决策阶段：报名前的候选收敛阶段；用户已有初步候选，但因资格、统考名额、科目迁移或成本冲突无法收敛。
- 有效结果：形成候选清单、确认没有合适项目、等待正式信息或暂缓考研，四者都可以是正确结果。

用户不满足任一条件时不进入首轮效果和盈利实验，可以记录为后续研究线索，但不能并入当前指标分母。

## 5. 为什么选择这组项目

这组计划身份用于覆盖三所北京院校、学硕/专硕、不同专业代码，以及往年材料中出现过的英语一/二、数学一/二、408/院校自命题、资格和培养规则差异。选择理由是形成有差异的工程和任务样本，不是学校排名，也不代表这些项目更值得报考。

## 6. 发布、替换与扩展规则

1. 项目只有在 2027 招生单位官方目录或简章发布、培养单位与项目身份核对、P0 字段完成独立复核后，才能从 `pending_publication` 进入可参与结论的状态。
2. 项目未发布、停招、改码、拆分或合并时仍保留在 V1 分母中；记录状态和原因。任何替换都创建 V2，不回写 V1。
3. 当前证据覆盖、待发布、状态透明和双人复核均以 V1 应有字段为分母；发布状态只能改变分子。
4. 在 V1 通过数据门槛、完成一次真实来源变更演练且运营工时可承担前，不增加院校、城市、专业代码或学习方式。
5. V2 只能扩大同一已验证用户任务；若改变地域、报考路径、用户阶段或学习方式，必须建立新的研究 cohort 和效果基线。
