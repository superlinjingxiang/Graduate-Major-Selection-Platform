# GradMatch 正式产品需求（PRD）

**版本：V1.3｜状态：开发基线｜更新日期：2026-09-01**

**战略依据：`docs/gradmatch-product-strategy-and-requirements.md`**

## 1. 文档规则

本文件是已确认、可开发、可测试的产品行为唯一清单。战略目标、范围和发布门槛由战略基线维护；技术实现由 `docs/architecture.md` 维护。没有需求 ID 的想法不进入开发验收，代码现状也不能反向替代产品需求。

### 1.1 状态与优先级

| 字段 | 含义 |
| --- | --- |
| 已确认 | 用户已经明确确认的行为，变更需重新确认。 |
| 基线 | 为实现已确认产品目标所必需的行为，可进入设计和开发；用户反馈可继续调整。 |
| P0 | 当前纵向链路必须具备；缺失时不能进入邀请制试点。 |
| P1 | 邀请制试点应具备；可以排在首个纵向链路之后。 |
| P2 | 公开小流量或后续阶段需求；不得阻塞首个闭环。 |

“能力门控”表示需求只在对应能力启用前成为阻断项。首个无 LLM 邀请链路保持 AI 功能标志、路由和调用全部关闭，即满足 AI 能力尚未启用的基线；一旦准备启用外部 AI，GM-AI-001/002/003 与对应 `GateDecision` 全部变为阻断项。

每项需求包含状态、优先级、依赖和可观察的验收条件。改变招生资格三态、候选分组、证据可信规则、隐私边界或商业排序隔离属于产品语义变更，必须同时更新战略基线和本文件。

### 1.2 全局验收规则

- 首期只显示明确目标年度内、全国统一考试路径下已纳入试点的项目；页面必须展示包含与排除范围。
- 所有时效性事实必须显示证据状态；没有当前有效证据时只能显示“待发布”或“待核验”。
- “优先比较、备选比较”只表达用户偏好下的比较顺序，不得出现“冲、稳、保”、录取概率、上岸分或保录取暗示。
- 资格判断只允许 `eligible_known`、`needs_confirmation`、`ineligible_known` 三种状态。
- 用户未确认的对话抽取结果不能参与硬约束判断。
- 调查比例、行业工资和更宽范围职业数据不得直接成为用户权重或项目结果。
- 付费、合作、赞助或广告状态不得改变资格、自然排序、证据等级和推荐理由。
- 普通用户界面不得展示服务、数据库、缓存、对象存储、环境、版本或模型诊断信息。
- P0 流程必须支持键盘操作；状态不能只依赖颜色；窄屏下不得丢失关键事实和证据入口。
- 所有 API 类型由生成客户端或平台无关领域模型提供，不在页面中复制定义。
- 访客必须能在注册前完成一次基础资格、证据比较和决策快照；账户只用于保存、同步、提醒、协作或购买。
- “无合适项目”“等待正式信息”或“暂缓考研”是合法结果，不得为了激活或付费强行推荐项目。
- 关键资格、影响结论的事实/未知、官方来源、S0/S1 更正和资格失效提醒不得被付费墙遮挡。

## 3. 账户与公开体验

### GM-AUTH-001 注册密码显示或隐藏

**状态：已确认｜优先级：P0｜依赖：注册页密码字段**

密码输入框右侧提供眼睛图标按钮。默认隐藏；切换时保留密码、焦点和光标位置。按钮必须支持鼠标、键盘和屏幕阅读器，并以“显示密码”或“隐藏密码”表达下一步动作。

**验收标准**

1. 打开注册页时密码不可见。
2. 输入密码后切换为明文，内容、焦点和光标位置不变。
3. 再次切换恢复掩码，内容仍不变。
4. 仅使用键盘和屏幕阅读器也能获知状态并完成切换。

### GM-AUTH-002 注册密码最低 8 字符

**状态：已确认｜优先级：P0｜依赖：Web 校验、Django 认证配置**

注册和密码登录相关设置统一要求密码至少 8 个字符；不得在前端接受、服务端拒绝同一个长度。

**验收标准**

1. 页面提示“密码至少需要 8 个字符”。
2. 8 个字符可提交，不因长度被拒绝。
3. 7 个及以下字符在前端和服务端均被拒绝，并显示相同语义的提示。

### GM-PUB-001 公开页面隐藏平台运行信息

**状态：已确认｜优先级：P0｜依赖：首页、公共错误组件**

公开页面不展示健康状态、依赖连接、环境名称、构建版本或内部架构。异常只返回与当前操作有关的用户提示和可供支持查询的非敏感事件编号。

**验收标准**

1. 未登录用户浏览首页、注册和登录页面时看不到内部运行信息。
2. API、数据库、缓存或对象存储异常时，页面不泄露依赖名称、主机、堆栈或诊断细节。
3. 内部健康接口和监控可以继续存在，但不出现在普通用户导航和内容中。

### GM-OPS-001 内部运维与用户错误隔离

**状态：基线｜优先级：P0｜依赖：错误映射、日志和监控**

**验收标准**

1. 用户可区分输入错误、暂时不可用、权限不足和资源不存在，并获得下一步建议。
2. 服务端日志保留关联事件编号和脱敏诊断；用户消息只包含事件编号。
3. 模型或数据服务不可用时遵守 GM-AI-002，不回显供应商响应。

## 4. 范围、偏好与资格

### GM-SCOPE-001 明示首期覆盖边界

**状态：基线｜优先级：P0｜依赖：目标年度、招生路径和覆盖配置**

**验收标准**

1. 用户开始配置前能看到 [`pilot-scope-2027-v1`](research/pilot-scope-2027-v1.md) 冻结的目标入学年度 2027、北京地域、全国统一考试、全日制和候选收敛阶段。
2. 同一位置明确排除其他地域、非全日制、推免、单独考试、专项计划、军队系统、博士和海外申请。
3. 搜索无结果时区分“当前试点未覆盖”和“已覆盖但没有匹配项目”。
4. 页面不得使用“全国全部项目”或同义表述，除非分母和审计确实覆盖全量。

### GM-COVER-001 冻结试点覆盖分母

**状态：基线｜优先级：P0｜依赖：CoverageManifest、年度项目**

**验收标准**

1. 工程原型和邀请制 `CoverageManifest` 必须逐项使用 [`pilot-scope-2027-v1`](research/pilot-scope-2027-v1.md) 冻结的 3/10 个计划项目 ID、年度、范围、版本和冻结时间；计划身份不等于 2027 已招生。
2. 分别报告项目纳入覆盖率、当前一手证据覆盖率、`pending_publication` 比率和已发布声明独立复核率；不得合并成一个“完整率”。
3. 未收录、资料不足或退出的项目仍在原 manifest 分母中，记录原因并通过新版本调整范围，不能删除后美化历史指标。
4. 正式目录尚未发布时，预告和往年数据只能作为背景；相关字段为 `pending_publication`，不得返回当前肯定结论。
5. 资格三态自动测试可使用隔离的 `synthetic` 或 `reference_year=2026` fixture；生产序列化器拒绝 fixture 数据，且它们不能计入 2027 覆盖率、证据状态或用户结论。

### GM-GOAL-001 读研目标确认

**状态：基线｜优先级：P0｜依赖：目标卡、用户确认**

**验收标准**

1. 用户在择校前确认一个首要目标，并可选次要目标；选项至少包含就业前景、职业发展、学术研究、学校提升和转换专业。
2. 用户可填写自定义目标或选择“尚不确定”；未确认目标不能被 AI 自动补全。
3. 目标只调整提问顺序和偏好解释，不直接改变资格状态或生成默认权重。
4. 选择“因就业困难暂时读研”或同义目标时，同时展示目标职业是否要求硕士、读研总成本及直接就业等替代路径，不作价值判断。
5. 目标修改后保存新版本，并能说明哪些提问或比较维度因此变化。

### GM-TAX-001 专业目录与历史映射

**状态：基线｜优先级：P0｜依赖：目录版本、专业代码、年度项目**

**验收标准**

1. 专业导航明确显示目录版本与实际存在的目录层级；2022 版目录的 67 个专业学位类别必须标明为博士 36 个、硕士 31 个，不得误写成 67 个硕士类别。
2. 旧代码通过有来源和生效时间的映射关联新代码，不覆盖或改写历史年度项目。
3. 同名不同码、同码不同年度名称和学校自设方向不得自动合并。
4. 首个试点只覆盖冻结清单中的 0812、0835、0839、085404、085405、085410；其他代码显示“当前试点未覆盖”。
5. 目录或映射不确定时，项目可以被收录为待核验，但不得参与自动筛选和职业结果合并。
6. 目录使用带父节点的 `TaxonomyNode`；年度项目可直接挂一级学科、专业学位类别、专业领域或院校自设节点，不强制经过同一层级。
7. 映射状态至少包含 `mapped`、`ambiguous`、`unmapped`、`institution_specific`；“对应”不得自动解释为培养内容相同。

### GM-DEG-001 学硕/专硕证据化比较

**状态：基线｜优先级：P0｜依赖：GM-TAX-001、年度项目、职业结果证据**

**验收标准**

1. 比较培养目标、课程/成果、实践、初试科目、学制学费、读博和职业路径，并逐项显示适用层级和来源。
2. 页面明确两类学位地位同等、定位不同，不显示“含金量”“社会地位”或综合高低分。
3. 全国或学科层面的描述标记为背景，具体考试、培养和费用必须来自年度项目或培养单位来源。
4. 某项差异缺少适用证据时显示未知，不按学位类型经验推断。

### GM-PREF-001 区分硬约束和可权衡偏好

**状态：基线｜优先级：P0｜依赖：平台无关偏好模型**

**验收标准**

1. 用户可把条件标记为硬约束或偏好并调整权重。
2. 硬约束只影响资格或排除；偏好只影响 `eligible_known` 项目的比较顺序。
3. 未填写的非必要偏好不阻塞结果，也不按零分惩罚项目。
4. 用户修改条件后，结果保存新版本且可以说明变化来自哪个条件。

### GM-PREF-002 对话事实必须由用户确认

**状态：基线｜优先级：P0｜依赖：对话层、事实卡**

**验收标准**

1. AI 从自然语言抽取的每项背景和偏好先进入“待确认事实卡”。
2. 用户可确认、修改或删除事实；未确认事实不参与硬约束和排序。
3. 对话只追问会显著改变候选集的缺失项，并允许用户跳过。
4. 对话不得要求身份证、精确地址、银行卡、健康信息、完整成绩单或证件图片。

### GM-PREF-003 实验性偏好表达

**状态：基线｜优先级：P1｜依赖：GM-GOAL-001、PreferenceFactorDefinition**

**验收标准**

1. 每个偏好因素有版本化定义、允许证据、适用范围、未知处理和解释模板。
2. 产品实验“最多三项并分配 100 点”、成对比较和自然语言取舍；在结果证明前不把任一方法设为安全决策前置条件。
3. 历史调查比例不预填为用户权重；页面可以解释来源边界但不能暗示“多数人的权重就是你的权重”。
4. 用户可跳过偏好设置并使用非个性化稳定排序；系统不得静默使用默认人格或人群均值。
5. 偏好只能影响 `eligible_known` 项目的比较顺序，不能覆盖硬约束、证据范围或未知状态；修改后显示分项变化，不显示百分制总分。

### GM-TRANS-001 跨专业与科目迁移成本

**状态：基线｜优先级：P0｜依赖：资格证据、初试科目、目录映射**

**验收标准**

1. 每个候选显示前置专业限制、同等学力/跨专业加试、初试科目组合、复试机试或实践要求及来源。
2. 用户可比较现有备考科目与候选要求的相同、需新增和未知部分；未知不按零成本处理。
3. 跨专业资格无法从已发布规则确认时返回 `needs_confirmation`，并生成向招生单位核验的具体问题。
4. 英语一/二、数学一/二、全国统考和学校自命题有明确标识；不可比试卷的历史分数不得直接排序。
5. 不根据专业名称相似度自动宣称可调剂；调剂兼容性必须绑定目标年度规则和招生单位要求。

### GM-COST-001 读研总成本比较

**状态：基线｜优先级：P0｜依赖：学制、费用、住宿、奖助证据**

**验收标准**

1. 分别显示目标年度学制、每年/总学费、住宿资格与费用、奖助资格和校区；每项都可回源。
2. 总成本按“官方总学费＋住宿＋用户估算生活成本＋机会成本－已确认奖助”计算，并展示公式和用户假设。
3. 竞争性奖学金不默认扣除；只公布上一年度收费时显示“目标年度待发布”。
4. 生活和机会成本由用户自愿填写区间，不要求精确收入，不推断非全日制用户能保持原收入。
5. 未知费用保持未知，系统不得用同校、同学位或往年数据静默填充。

### GM-ELIG-001 报考资格三态判断

**状态：基线｜优先级：P0｜依赖：已确认用户事实、EvidenceClaim、RuleVersion**

**验收标准**

1. 所有适用硬规则满足时返回 `eligible_known`，并显示“不代表录取可能性”。
2. 官方信息未发布、规则歧义、来源冲突或用户事实不足时返回 `needs_confirmation`，列出缺口和向招生单位核验的问题。
3. 至少一条适用硬规则明确不满足时返回 `ineligible_known`，显示规则、用户事实和证据。
4. 用户修正事实或证据版本变化后重新判断，并保留旧结果用于审计。
5. 同等学力、跨专业、工作年限、境外学历认证和非全日制定向就业无法明确判断时必须进入 `needs_confirmation`。
6. API、页面、导出和 AI 解释不得产生第四种资格语义或“可能符合”等模糊文案。

### GM-RULE-001 规则全集与确定性资格

**状态：基线｜优先级：P0｜依赖：RuleSetRevision、CoverageManifest、EligibilityCheck**

**验收标准**

1. 每个冻结年度项目有版本化规则全集，记录规则、适用性、优先级、证据引用、覆盖状态、发布人和生效时间。
2. 任一已确认且适用的硬规则失败时返回 `ineligible_known`；否则只要规则适用性、用户事实、来源或规则未知/冲突，就返回 `needs_confirmation`。
3. 只有规则全集已发布且所有适用检查通过时才能返回 `eligible_known`；“未发现限制”不得等同“已确认符合”。
4. 每次判断保存 `EligibilityCheck(rule_revision, applicability, input, result, reason, evidence_usage)`，相同输入与版本产生相同结果哈希。
5. 黄金规则矩阵覆盖明确失败、缺失用户事实、来源冲突、适用性未知、规则未发布和全部通过。

## 5. 项目发现、比较与行动

### GM-CAT-001 项目发现与证据状态

**状态：基线｜优先级：P0｜依赖：年度招生项目、覆盖配置**

**验收标准**

1. 搜索和筛选只返回当前选择年度与路径内的项目。
2. 每张项目卡显示年度、培养单位、专业项目、学习方式和资料状态。
3. 资料状态至少区分已核验、待发布、待核验、存在冲突和已过期。
4. 卡片提供官方来源入口；缺少 P0 证据的项目不得显示肯定式资格结论。

### GM-CAT-002 项目详情逐字段回源

**状态：基线｜优先级：P0｜依赖：SourceDocument、EvidenceClaim**

**验收标准**

1. 资格、科目、学习方式、费用、关键日期和招生计划说明分别显示值、状态、适用年度、来源及核验时间。
2. 用户可从字段打开原始官方链接；系统同时保留不可变快照和原文定位供审核。
3. 原链接失效时显示失效状态和最近核验时间，不静默改用往年或低等级来源。
4. 多来源冲突未裁决时显示冲突内容并使相关资格进入 `needs_confirmation`。

### GM-ADM-001 招生计划分母拆分

**状态：基线｜优先级：P0｜依赖：年度项目、招生计划证据**

**验收标准**

1. 分别保存和显示总计划、推免、全国统考、专项、联合培养及最终实际录取；每个值有独立状态和来源。
2. 含推免总计划不得以“统考名额”或同义文案展示；只公布总计划时统考名额显示未知。
3. 计划类别可能重叠或口径不完整时不得强制相加，页面展示招生单位原始说明和缺口。
4. 计划调整形成年度内变更事件，旧值可审计，保存方案按 GM-DATA-003 识别影响。
5. 推免和专项虽不属于首期申请路径，仍可作为统考分母背景显示，但不能生成这些路径的申请建议。

### GM-ADM-002 报考竞争证据

**状态：基线｜优先级：P1｜依赖：复试录取证据、去标识化聚合**

**验收标准**

1. 可展示国家/学校/学院复试线、差额比例、复试权重、总成绩公式，以及有官方分母的报考、复试和录取人数。
2. 历史录取分布只在样本充分、已剔除或标记专项路径并完成去标识化时展示中位数和四分位数。
3. 页面标记科目组合与试卷可比性；不可比数据不得进入跨项目难度排序。
4. 任何历史线、人数或分布均不得转换成个人录取概率、“冲稳保”或保证性结论。
5. 不保存或展示公开名单中的姓名、考号、联系方式等个人标识。

### GM-CAREER-001 学位与职业路径证据

**状态：基线｜优先级：P0｜依赖：GM-DATA-004、职业分类与资格目录**

**验收标准**

1. 首个试点至少说明计算机相关学硕与电子信息相关专硕在研究、实践、企业研发、教学科研和继续深造上的路径差异。
2. 全国或学科研究必须显示调查届次、教育层次、样本范围和来源，并标记 `broader_context`，不得冒充目标项目结果。
3. 薪资只在能区分起薪、毕业后收入和行业全体工资时展示；行业平均值必须明确标记为背景。
4. 页面不输出“专硕就业一定更好”“学硕地位更高”或同义结论，不生成社会地位总分。
5. 缺少职业证据不影响报考资格，但作为信息缺口显示且不进入偏好得分。

### GM-CAREER-002 项目级职业结果

**状态：基线｜优先级：P1｜依赖：同口径项目样本、GM-DATA-004**

**验收标准**

1. 仅 `exact_match` 证据可显示为项目结果，并展示直接就业、升学及其他去向的分解。
2. 同时显示职业、行业、单位性质、地区、专业相关度，以及起薪中位数/四分位数；无数据的维度保持未知。
3. 每个比例展示分子、分母、观察窗口、样本量和响应率；宣传材料缺少定义时不得进入项目比较。
4. 不同定义、届次、学习方式或学位类型的数据不得合并排名。

### GM-CAREER-003 可解释职业特征

**状态：基线｜优先级：P1｜依赖：国家职业分类、国家职业资格目录、范围明确的调查**

**验收标准**

1. 职业名称映射国家职业分类，资格区分法定准入类、水平评价类和无国家职业资格要求。
2. 分别展示稳定性、收入波动、工作强度、地域集中度、专业相关度和深造空间，不合并为社会地位分。
3. 客观规则、统计观察和主观调查在界面上明确分区；主观数据必须显示问题文本、人群、地区和年份。
4. 用户可以为职业特征设置自己的偏好，平台不提供带价值判断的默认高低排序。

### GM-CMP-001 候选项目对比

**状态：基线｜优先级：P0｜依赖：GM-CAT-002**

**验收标准**

1. 用户可同时对比 2–5 个项目。
2. 对比表按同一字段顺序显示值、缺失、差异和证据状态。
3. 未知值单独显示，不等于零、不利或不满足。
4. 键盘和窄屏用户可以查看每个候选的全部 P0 字段及来源。

### GM-CMP-002 培养、成本、竞争与职业综合对比

**状态：基线｜优先级：P1｜依赖：GM-DEG-001、GM-COST-001、GM-ADM-002、GM-CAREER-001**

**验收标准**

1. 同一对比表按培养、资格/考试、名额、成本、竞争证据和职业路径分组展示。
2. 每个数字显示单位、年度、范围和证据状态；不同口径不可比较时显示原因而非空白或零。
3. 用户可以隐藏不重要的分组，但不能隐藏硬约束冲突和 P0 证据缺口。
4. 商业权益只能控制深度、保存或提醒能力，不改变基础事实、自然顺序和差异判断。

### GM-REC-001 无概率的候选分组与解释

**状态：基线｜优先级：P0｜依赖：GM-PREF-001、GM-ELIG-001**

**验收标准**

1. 结果只使用“优先比较、备选比较、待核验、已排除”四类。
2. `eligible_known` 才能进入前两类；`needs_confirmation` 只能进入待核验；`ineligible_known` 默认进入已排除。
3. 每个前两类项目展示参与排序的偏好、权重、满足情况、未知项和具体取舍。
4. 未知偏好不按零分处理；相同偏好结果保持真实并列，证据完整度只影响可信状态，不作为适配优胜条件；页面可按项目名称做稳定的非语义顺序。
5. 页面、接口和导出均不得输出录取概率、上岸分、“冲稳保”或保证性表述。
6. 用户关闭个性化后可查看不使用其偏好权重的稳定排序。

### GM-ACT-001 可执行行动清单

**状态：基线｜优先级：P0｜依赖：方案、关键日期和来源**

**验收标准**

1. 每个行动包含对象、动作、状态、适用日期或“日期待发布”、官方链接和产生原因。
2. `needs_confirmation` 至少生成一个具体核验问题，不能只写“请自行确认”。
3. 来源或规则变化后，受影响行动被标记并生成更新记录。
4. 用户可以完成、忽略或重新打开行动；操作不改变官方事实。

### GM-DEC-001 决策快照与有效结果

**状态：基线｜优先级：P0｜依赖：比较、行动、事实/规则/证据版本**

**验收标准**

1. 用户无需注册即可生成一次决策快照；注册只用于保存、跨设备同步、更新提醒、协作或购买。
2. 快照必须选择 `shortlist_ready`、`no_suitable_offering`、`awaiting_official_information`、`postpone_application` 之一，并包含对应的保留、排除和延后候选，用户确认理由、关键未知、下一步、复查日期、`comparison_run_id`、事实/规则/证据版本和生成时间。
3. 每个 `needs_confirmation` 有原因码，例如 `rule_unpublished`、`source_conflict`、`user_fact_missing`、`applicability_unknown`，并可映射为具体行动。
4. “无合适项目”“等待正式信息”或“暂缓考研”可被保存为成功结果；指标不得要求用户必须保留项目。
5. 快照不显示或保存录取概率、综合成功率或标量置信度，只逐字段展示 `current`、`pending_publication`、`needs_review`、`conflict`、`expired` 等证据状态；旧快照不可原地覆盖。
6. 访客快照由随机、短期、仅限该资源的能力令牌访问；服务端只保存令牌哈希。注册后必须用已认证会话和有效能力令牌显式认领，认领成功即轮换/撤销访客令牌，不能枚举或认领他人快照。

### GM-COR-001 纠错案件闭环

**状态：基线｜优先级：P0｜依赖：审核工作台、通知**

**验收标准**

1. 用户可选择项目和字段，提交建议、官方链接及说明。
2. 案件状态至少包含已提交、审核中、已接受、已拒绝和已发布。
3. 未审核投稿不进入事实、资格和排序。
4. 处理记录包含处理人、证据、结论和理由；提交者能查看状态。
5. 变更发布后触发 GM-DATA-003 并通知受影响用户。

## 6. 数据可信与可重放

### GM-DATA-001 来源准入与不可变快照

**状态：基线｜优先级：P0｜依赖：DataSource、Celery、对象存储**

**验收标准**

1. 每个真实来源记录责任人、允许路径、robots/条款检查、限速、更新事件和失败阈值。
2. 采集不绕过登录、验证码、访问控制或明确禁止的技术措施。
3. 内容按哈希保存为 `RawBlob`；每次访问无论内容是否重复都新增 `SourceFetch`，记录 URL、时间、HTTP 状态、ETag/Last-Modified、运行和 blob 引用。
4. 不允许自动采集的来源使用人工录入原始文件，仍执行同样的哈希和审核流程。
5. 失败不会覆盖最后一个已发布版本，错误记录必须脱敏。
6. 抓取器限制允许域名和解析后 IP，阻断私网/元数据地址，逐次复核重定向，并限制响应大小、MIME、超时和真实请求速率；负向测试覆盖 SSRF 与资源耗尽。

### GM-SRC-001 来源权利与展示边界

**状态：基线｜优先级：P0｜依赖：来源评估、制品分层、下架流程**

**验收标准**

1. 每个来源在生产采集或展示前记录权利基础、允许提取/保存/加工/公开展示的范围、条款与 robots 检查日期、责任人和下架方式；技术可访问不等于获得内容权利。
2. 原始快照与公开证据制品隔离；公开页只显示实现用户核验所需的最小摘录、定位和链接，并处理个人信息与受保护内容。
3. 来源禁止自动化、要求登录/验证码、权利基础不明或收到异议时立即停采/下架，保留审计并切换为授权录入或仅链接。
4. 公开来源中的联系方式、姓名等信息不能因“公开”而自动进入个性化、训练、营销或转售用途。

### GM-DATA-002 证据审核、冲突与过期处理

**状态：基线｜优先级：P0｜依赖：后台、EvidenceClaim、RuleVersion**

**验收标准**

1. 解析出的声明默认不可见且不能参与规则，只有人工核验并发布后才可使用。
2. 每项声明包含规范值、原文值、适用范围、原文定位、来源等级、版本和审核记录。
3. 资格、科目、学习方式、费用、关键日期或招生计划冲突时暂停自动结论，相关资格为 `needs_confirmation`。
4. 过期或被替代证据仍可审计，但不参与当前结果。
5. 邀请制发布必须通过战略基线 6.4 的数据门槛。

### GM-DATA-003 方案可重放与变更重算

**状态：基线｜优先级：P0｜依赖：证据、规则和方案版本**

**验收标准**

1. 方案保存用户事实版本、偏好权重、规则版本、证据版本、排序参数、模型版本和生成时间。
2. 使用保存版本能确定性重现资格状态、候选分组和排序结果哈希；LLM 文案不要求重新调用后逐字一致，而是保存原响应、模板、输入快照和验证结果。
3. 证据或规则发布新版本后能识别受影响方案，并在批准后 1 个工作日内重算。
4. 用户看到变更摘要、旧值、新值、来源和受影响行动；旧方案不被物理覆盖。

### GM-AUDIT-001 不可变审计与幂等事件

**状态：基线｜优先级：P0｜依赖：AuditEvent、OutboxEvent、JobExecution**

**验收标准**

1. 来源访问、证据复核/发布、规则发布、资格运行、纠错、重算、通知、导出和删除产生追加式审计事件，业务管理员不能修改或删除历史事件。
2. 录入者不能复核自己的 P0 声明，编辑者不能绕过发布动作；角色和审批有自动化权限测试。
3. 发布与待处理事件在同一数据库事务中写入 outbox；重算和通知使用幂等键，一次纠错发布最多产生一次有效重算和一次对应通知。
4. 对象写入与数据库状态使用可恢复协议；故障演练不会留下无法识别的孤儿对象或悬挂引用。
5. 审计记录不保存密钥、完整对话或不必要的个人信息，并按记录类别适用的期限与访问控制保留。

### GM-DATA-004 职业结果范围与口径校验

**状态：基线｜优先级：P0｜依赖：MetricDefinition、EvidenceScope、CareerOutcomeEvidence**

**验收标准**

1. 每个职业结果包含教育层次、学位类型、学习方式、目录版本、专业/学校/项目范围、毕业届次、观察窗口、地区、行业、统计量、分子、分母、样本量、响应率和来源。
2. 服务端只返回 `exact_match`、`broader_context`、`incompatible` 三种范围结论，并保存判定理由和规则版本。
3. `broader_context` 不参与项目排序；`incompatible` 不进入项目卡和比较 API。
4. 本科结果不得标成硕士结果，行业工资不得标成应届起薪，学校整体数据不得标成项目结果；未分组或分组口径、届次、观察窗不一致的混合学位样本不得比较，同源同届且定义一致、分组充分的样本可以比较。
5. 底层分别保存 `entity_match`、`population_match`、`time_match`、`metric_match`、`mode_match`，前台三态不得隐藏某个维度的不兼容。
6. 指标定义或范围规则变化后触发受影响结果重算；旧判断可审计。

## 7. AI、隐私与用户权利

### GM-AI-001 AI 输出证据合同

**状态：基线｜优先级：P1（能力门控）｜依赖：LLM 网关、JSON Schema、证据 API**

**验收标准**

1. 模型只能接收最小必要的已确认事实和服务端提供的候选证据，不可直接访问任意网页或 SQL。
2. 输出包含候选 ID、资格状态、理由、`evidence_id`、信息缺口和行动；服务端 Schema 校验后才渲染。
3. 无效候选、无效证据 ID、证据与陈述不一致或出现保证性表述时整份 AI 结果被拒绝。
4. AI 只能解释规则结果，不能创建招生事实、资格状态或录取概率。
5. AI 功能关闭时不存在用户可达路由、UI 或模型调用；只有启用前才要求本节全部验收通过。

### GM-AI-002 AI 失败安全降级

**状态：基线｜优先级：P1（能力门控）｜依赖：已核验目录与比较页**

**验收标准**

1. 模型超时、预算耗尽、供应商失败或证据校验失败时，用户仍可使用已核验搜索、详情和对比。
2. 降级页面列出待核验问题，不生成看似完整的自由文本方案。
3. 用户消息不展示供应商、模型响应、密钥、堆栈或内部诊断。
4. 启用任何 AI 解释前，本节降级路径必须完成超时、预算、供应商失败和 Schema 拒绝演练。

### GM-AI-003 AI 标识、投诉与人工复核

**状态：基线｜优先级：P1（能力门控）｜依赖：支持和审核流程**

**验收标准**

1. AI 生成解释在页面、导出和分享中有适用的显式标识，下载内容写入适用的隐式标识/元数据，并显示生成时间、数据版本和模型版本的用户可理解摘要。
2. 用户可以针对事实、资格、解释或隐私问题发起投诉/纠错并查看状态。
3. S0/S1 反馈触发相关结果暂停和人工复核，不等待一般工单时限。
4. 外部 AI 的 `GateDecision` 未放行或本节未通过时，能力保持关闭；无 LLM 的首次邀请制链路不因此被阻断。

### GM-PRIV-001 数据最小化与分层保留

**状态：基线｜优先级：P0｜依赖：账户、偏好、审计存储**

**验收标准**

1. 首期默认不收身份证、精确地址、银行卡、健康/心理信息、完整成绩单或证件图片。
2. 原始对话、结构化偏好、身份账户和审计日志逻辑隔离并使用最小权限。
3. 原始对话默认 30 天自动删除；不使用真实对话训练通用模型。
4. 模型供应商配置必须禁止使用输入训练通用模型，并记录处理地区、保留和分包信息。
5. 进入个性化方案前只询问用户是否已满 18 周岁，不收集生日或身份证号；确认未满 18 周岁或拒绝确认时，只能使用非个性化公开信息。

### GM-PRIV-002 查看、更正、导出和删除

**状态：基线｜优先级：P0｜依赖：账户设置、导出和删除任务**

**验收标准**

1. 用户可查看、更正、导出和删除与其关联的账户、对话、结构化偏好、事实卡、保存项目、方案、研究记录、分析事件、支持记录、订单及设备/登录数据（依法必须留存的除外）。
2. 删除发起后立即停止使用相关数据；主要业务库 7 天内删除，备份副本 30 天内随轮换清除。
3. 法定必须留存的记录单独隔离，并向用户说明类别、原因和期限。
4. 删除演练能用事件编号证明各数据层处理完成，但不在普通页面暴露内部存储信息。

### GM-PRIV-003 数据生命周期与供应商治理

**状态：基线｜优先级：P0｜依赖：数据清单、供应商清单、保留策略**

**验收标准**

1. 账户、对话、研究、行为分析、支持、订单、设备/登录、网络日志、业务审计和证据制品分别记录目的、法律/业务依据、字段、访问角色、处理地区、共享方和保留期限。
2. 可关联到个人的“匿名账户/会话 ID”统一按去标识化个人信息治理，不宣称已匿名；聚合发布需通过重新识别风险检查。
3. 模型、分析、邮件、对象存储等供应商及其分包商在接入前完成用途、训练使用、地域、保留、删除、事件通知和跨境适用性评估。
4. 自动化决策在适用时完成影响评估、公平性与准确性测试、非个性化选择和人工复核；年龄 18+ 是产品范围选择，不冒充法定未成年人定义。
5. 各类日志按适用法律和业务必要性分别保留；网络日志不得以统一 180 天或更短天数规避适用的法定最低期限。

## 8. 测量与商业验证

### GM-METRIC-001 统一记录真实决策事件

**状态：基线｜优先级：P0｜依赖：服务端埋点**

**验收标准**

1. 服务端记录 `landing_view`、`match_start`、`match_submit`、`result_view`、`source_open`、`save_or_compare`、`project_removed`、`decision_snapshot_created`、`criteria_revised`、`official_question_created`、`action_completed`、`result_update_view`、`return_d30`、`feedback_submit` 和 `correction_resolved`。
2. 事件包含去标识化用户/账户标识、会话、时间、来源归因、试点范围和产品版本，不记录对话原文或敏感事实；可关联标识仍按个人信息治理。
3. 可信候选清单完成率必须按“保存/比较至少 2 个候选＋打开至少 1 个官方来源＋生成至少 1 个行动”的同一用户计算。
4. 任何比率报告同时显示分子、分母、窗口和 cohort；样本不足 30 时标记为探索性观察。
5. 任务回放记录资格、名额分母、总成本和证据范围的正确率、完成时间、虚假确信、S0/S1 误导和用户报告伤害；点击或注册不能单独证明用户价值。

### GM-RESEARCH-001 决策因素持续校准

**状态：基线｜优先级：P1｜依赖：研究样本、产品行为事件**

**验收标准**

1. 首轮研究严格聚焦“2027 年、北京、全日制、全国统考、计算机相关、已有初步候选但因资格/名额/科目/成本无法收敛”的冻结微人群；访谈只用于发现模式，不报告全国比例。
2. 访谈记录功能任务、情绪/社会压力、决策自主权、当前最强免费替代、购买者/使用者/影响者/否决者和实际错误；结构化问卷只在构念验证后使用。
3. 便利样本明确标记为不可代表全国；分层结果在样本不足时标记探索性。
4. 调查比例不得自动写入个人权重；每个招生年度重新检查问题顺序。
5. 长期校准优先使用任务正确率、`criteria_revised`、`source_open`、候选保存/删除、更新查看和行动完成等真实行为；“无合适项目/等待信息/暂缓考研”计入有效决策。
6. “优于最强免费替代”的判断必须执行 [`free-alternative-protocol-v1`](research/validation-protocol-v1.md) 冻结的匹配任务、顺序平衡、盲评、排除规则、严重度和预登记通过条件；样本不足或协议破坏只能记为 `inconclusive`。

### GM-COM-001 付费权益与自然结果隔离

**状态：基线｜优先级：P1｜依赖：经营主体、商户支付、订单/退款/开票、Entitlement**

**验收标准**

1. 付费权益可以控制深度比较、保存数量、变更提醒或协作能力，但不能改变资格、证据、自然排序、未知状态和推荐理由。
2. 主体、收款、订单、服务/退款规则、对账和开票未完成战略 Go 门槛时，不开放真实支付，只能使用无资金的实验标记。
3. 人工诊断包与软件报考季决策包分别记录实收、退款、支付费、直接复核、支持、模型/通知成本和贡献毛利。
4. 软件付费假设只有在无一对一代查时产生真实付款、预登记的关键报考节点行为（节点尚未到达时才用 D30 代理）和正贡献毛利才算通过。
5. 不出售用户线索；合作、广告和赞助信息与自然结果数据物理或权限隔离，并显著标识。
6. 权益服务不可用时不影响用户访问已购买期内的基础事实、来源和导出，并提供可审计的补偿/退款处理入口。
7. 商业关系不得影响项目收录、更新速度、证据展示位置、纠错优先级或资源推荐；审核人员和研究参与者披露并回避利益冲突。

### GM-COM-002 免费安全底线与完整盈利核算

**状态：基线｜优先级：P1｜依赖：权益矩阵、成本台账、商业实验**

**验收标准**

1. 免费层提供一次基础资格、关键事实/未知、官方来源、基础对比和决策快照；S0/S1 更正及资格失效提醒始终免费。
2. 付费权益只包含跨时间便利和增量能力，例如更多历史版本、深度对比、持续监控、协作、批量导出或更高 SLA；不得付费后才显示影响结论的事实。
3. 每个价格实验冻结权益、价格、渠道、交付边界、退款触发、补偿、平台/用户责任和样本；人工服务与软件包使用不同 offer 与台账。
4. 分别报告交付贡献毛利、扣除可归因付费获客后的贡献、年度经营利润和现金流；`有效激活成本` 不得命名为付费 CAC。
5. 数据运营记录录入、独立复核、返工、变更和客服工时；若成本随项目或用户近似线性增长，停止扩大软件盈利结论。
6. 软件盈利只有在无一对一代查的真实付款 cohort 扣除退款、支付、直接复核/支持、模型/通知和可归因获客后为正，且年度汇总的扣获客后贡献大于分配到该产品的年度固定成本时才算通过；不得用收入覆盖固定成本替代利润判断。
7. 每次扩大固定投入前提交未来 12 个月逐月现金流；承诺新增固定支出后仍保留不少于 6 个月已承诺支出的可用资金。“6 个月”是当前风险偏好，可由版本化经营决定调整。

### GM-GOV-001 分阶段外部发布门槛

**状态：基线｜优先级：P0｜依赖：研究、来源、AI、部署、支付评估**

**验收标准**

1. 外部用户研究前完成告知同意、退出/补偿、去标识化、保留和研究资料访问控制。
2. 真实来源采集或展示前完成 GM-SRC-001 及抓取安全评估；没有权利或安全依据时不进入生产。
3. 外部 AI 前冻结供应商、数据地域/保留/分包、自动化决策、显式/隐式标识及适用备案/登记的书面判断；不满足时仅运行无 LLM 闭环。
4. 公开 Web/APP 前完成与主体、域名、部署、业务形态一致的备案/许可、网络数据、安全分级保护等适用性判断与演练。
5. 真实支付或广告前完成经营主体、订单/合同、交付/退款、对账、开票、消费者权益、广告标识/用语及用户案例使用的书面评估。
6. 每次评估形成不可变 `GateDecision`：`state` 只能为 `pending`、`go`、`conditional_go`、`not_applicable_with_rationale`、`no_go`，并记录 `capability`、精确范围、`deployment_fingerprint`、审批人、证据引用、决定/到期时间、条件和被替代决定。
7. 能力激活必须匹配当前部署指纹；只有 `go`、条件已核验的 `conditional_go`，或有签署理由的 `not_applicable_with_rationale` 放行。`pending`、`no_go`、过期、条件未完成或供应商/地域/域名/主体等指纹变化均阻断。
8. 每个门槛只放行对应能力；不得以内部测试、备案完成或使用境外服务自动推导其他门槛已通过。
